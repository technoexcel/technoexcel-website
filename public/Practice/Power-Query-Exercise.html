Sales Consolidation and Master Data Merge

Monthly sales files arrive with inconsistent dates, messy product codes, missing customer IDs, and occasional products that do not exist in the master. Build one clean reporting table plus exception queries.

Core SkillsAppend, trim, type conversion, merge, anti-join, validation.
OutcomeOne enriched sales fact table ready for Power BI.

Scenario Flow

1ImportLoad each monthly file separately.
2CleanFix keys, dates, names, and types.
3MergeAdd customer and product context.
4AuditFind unmatched customers and products.

Business Objective

  • Create one clean sales table across all months.
  • Bring in customer region, segment, product category, and price fields.
  • Flag missing customers, missing products, and suspicious amount rows.

Deliverables

  • Sales_Combined query.
  • Sales_Final query.
  • Missing_Customers and Missing_Products exception queries.
  • LineCheck column for amount validation.

Power Query Steps

  1. Import each monthly sales file as a separate query.
  2. Trim and clean text fields, uppercase ProductCode, and proper case SalesRep.
  3. Set OrderDate, Quantity, and NetAmount to correct types.
  4. Append the monthly queries into Sales_Combined.
  5. Import and clean customer and product masters.
  6. Merge customer data on CustomerID, then merge product data on ProductCode.
  7. Add custom column LineCheck to compare amount versus quantity times unit price.
  8. Create left anti joins for missing customers and missing products.

Finance Trial Balance Cleanup and Mapping

Account codes and cost centers are inconsistent across source files. Build a mapped trial balance with account groups, department mapping, and separate exception tables for anything missing from the lookup data.

Core SkillsNormalize text, merge lookups, classify signs, build exceptions.
OutcomeFinance-ready table with clean account and department mapping.

Scenario Flow

ANormalizeUnify cost-center formats.
BMapJoin account and cost-center lookups.
CClassifyAdd debit-credit logic.
DAuditShow mapping gaps.

Business Objective

  • Prepare a clean trial balance with account and department context.
  • Standardize all cost-center variants into one comparable format.
  • Highlight missing account and missing cost-center mappings.

Deliverables

  • TB_Staging query.
  • TB_Final query.
  • Missing_Accounts query.
  • Missing_CostCenters query.
  • SignType column.

Power Query Steps

  1. Import trial balance, chart of accounts, and cost-center map files.
  2. Trim AccountCode and standardize CostCenter by uppercasing and removing spaces or hyphens.
  3. Set Amount to Decimal Number.
  4. Merge to the chart of accounts and expand descriptive fields.
  5. Merge to the cost-center map and expand department and location.
  6. Add conditional SignType based on the sign of amount.
  7. Create anti-join exception queries for missing account and cost-center matches.

HR Employee Master Consolidation

Employee data comes from the HRMS and a manual admin file. Names, department labels, and dates are inconsistent, and some employees appear more than once. The task is to build a trusted employee master.

Core SkillsAppend, dedupe, latest-record logic, standardization, null flags.
OutcomeOne employee master plus duplicate and missing-field review outputs.

Scenario Flow

1AppendBring both sources together.
2CleanFix names, departments, locations, and dates.
3PrioritizeKeep the latest record.
4ReviewFlag missing location and duplicates.

Business Objective

  • Combine employee data from both sources into one master.
  • Preserve the most recent row per employee.
  • Create employment status and missing-location flags.
  • Prepare a duplicate-review query.

Deliverables

  • Employees_Combined query.
  • Employees_Final query.
  • Duplicate_Review query.
  • EmploymentStatus and MissingLocationFlag columns.

Power Query Steps

  1. Import both employee files.
  2. Trim text fields, proper case names, and standardize department and location labels.
  3. Convert JoinDate, ExitDate, and LastUpdated to date types.
  4. Append both sources into one query.
  5. Sort by employee and latest update date, then remove duplicates by employee key.
  6. Add employment status from exit date and a missing-location flag.
  7. Create a grouped duplicate review query for suspicious repeated employees.

CRM Leads and Follow-Up Analysis

Raw CRM statuses vary, follow-up history sits in a different file, and not every lead has an owner or a next action. Build a pipeline-ready dataset with status mapping, follow-up visibility, and aging logic.

Core SkillsStatus mapping, merge, conditional logic, aging buckets, action views.
OutcomeOne lead table plus no-follow-up and blank-owner exception queries.

Scenario Flow

IStandardizeNormalize raw statuses.
IIEnrichAdd follow-up context.
IIIAgeCreate lead aging logic.
IVActSeparate operational gaps.

Business Objective

  • Standardize raw status labels into one sales funnel vocabulary.
  • Merge follow-up details into each lead.
  • Create follow-up flags, aging days, and aging buckets.
  • Highlight leads with no follow-up or no owner.

Deliverables

  • Leads_Final query.
  • FollowUpFlag, AgingDays, AgingBucket.
  • No_FollowUp query.
  • Blank_Owner query.

Power Query Steps

  1. Import leads, follow-ups, and status map files.
  2. Trim text fields and standardize lead IDs and statuses.
  3. Set date columns correctly.
  4. Merge leads to the status map and expand the standard status.
  5. Merge to follow-ups and expand date, type, and remarks.
  6. Add follow-up flag and aging calculations with conditional columns.
  7. Create reference queries for leads with no follow-up and leads with blank owners.

Survey Feedback Unpivot

Survey exports use one column per question, which is hard to analyze in Power BI. Convert the file into a long format where one row equals one response-question pair.

Core SkillsUnpivot, rename, clean response text, classify question groups.
OutcomeLong-format survey table ready for slicing by region, question, and customer type.

Scenario Flow

1KeepPreserve response metadata.
2UnpivotTurn question columns into rows.
3CleanFix response text.
4ClassifyCreate question groups.

Business Objective

  • Convert a wide survey export into a normalized long table.
  • Retain core respondent metadata.
  • Add a question-group field for easier reporting.

Deliverables

  • Survey_Long query.
  • Question and Response columns.
  • QuestionGroup derived field.

Power Query Steps

  1. Import the survey CSV file.
  2. Identify the metadata columns that must stay fixed.
  3. Select those columns and use Unpivot Other Columns.
  4. Rename Attribute to Question and Value to Response.
  5. Trim and clean the response column.
  6. Create a conditional question group based on the question name.

Operations KPI Reshaping

Branch teams submit weekly KPI sheets with KPI names as rows and weeks as columns. Leadership needs a branch-week-KPI table that works directly in dashboard visuals and trend analysis.

Core SkillsUnpivot, standardize labels, numeric typing, custom keys.
OutcomeNormalized KPI model for branch and weekly performance tracking.

Scenario Flow

ACleanFix branch and KPI labels.
BUnpivotMove weekly columns into rows.
CTypeConvert KPI values to numbers.
DKeyCreate branch-week-KPI ID.

Business Objective

  • Turn matrix-style KPI sheets into normalized rows.
  • Prepare the data for weekly trend reporting and branch comparisons.
  • Create a reusable business key for uniqueness.

Deliverables

  • Operations_KPI_Long query.
  • Week, KPIValue, and BranchWeekKPIKey.

Power Query Steps

  1. Import the operations KPI file.
  2. Trim branch and KPI columns and standardize their labels.
  3. Select identifier columns and use Unpivot Other Columns.
  4. Rename Attribute to Week and Value to KPIValue.
  5. Convert KPI value to Decimal Number.
  6. Create a custom key combining branch, week, and KPI name.
